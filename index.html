00 · 展示主线

这个网页要讲清楚的不是“一个检测模型”，而是“医疗数据安全闭环”

比赛答辩时建议围绕三句话展开：常驻基础防护先保护数据；AI 风险检测负责发现异常； Policy、Defense、Integrity、Recovery 和 Event Pool 负责把异常转化为可执行、可审计、可反馈的处置结果。

第一层 常驻基础保护

数据进入系统后即完成身份、分级、加密和双备份，不依赖攻击已经发生。

第二层 AI 风险感知

基于用户、文件、网络与上下文行为提取风险证据，输出风险分数和异常类型。

第三层 主动防御处置

根据风险与数据等级生成 P0–P3 策略，对权限、密钥、网络和水印动作进行收紧。

第四层 可信验证恢复

通过完整性证据与双备份恢复能力，保障异常后可以核验、可恢复、可追溯。

01 · 数据基础

先把医疗数据保护起来，再谈智能检测

资产身份、数据分级、AES-GCM 加密与 Local + Cold 双备份属于常驻基础防护； AI 异常检测负责在风险升高时进一步收紧策略，不是“事后才开始保护”。

数据说明： 当前展示对象包括 D1、D2、D3 与 Trap 诱捕资产。Trap 只作为策略上下文，不作为 AI 特征输入， 避免模型靠“诱捕标签”投机判断。

05 · 策略防御与恢复

07 · 答辩讲解

建议用这条讲解线索介绍系统

这部分是给展示者看的现场话术提示，帮助把网页内容讲成“系统方案”，而不是只念指标。

开场

我们做的是基层医疗数据安全防护系统，重点不是单点检测，而是把医疗资产保护、异常检测、策略处置、完整性验证和恢复闭环打通。

核心逻辑

正常情况下系统已经有数据分级、加密和双备份；AI 检测到风险后，策略层只是在原有保护基础上进一步收紧。

实验支撑

本页读取最终正式 run 的 JSON 与 CSV，展示资产规模、事件规模、检测性能、攻击遏制、误阻断、备份验证和恢复情况。

诚实边界
